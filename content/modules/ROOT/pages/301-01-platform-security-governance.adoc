**Duration:** ~25 minutes

== Overview
xref:201-11-threat-modeling-control-mapping.adoc[201-11] named the controls. This lab **ships them as an RHACM PolicySet** so every cluster in the Placement gets the same namespace, PSA, Quota, default-deny NetworkPolicy, and a ServiceAccount that does not automount a token.

That is the platform operating model: the security team owns the PolicySet; application teams consume `stride-workloads`. Inform first (report drift), then enforce (create the missing objects)—the same loop as xref:201-10-admission-governance.adoc[201-10], expanded to the STRIDE rows.

== Why it matters
A threat model in a slide deck does not configure the next cluster. RHACM Policy objects do. DoD CC SRG, DISA STIG, and NIST SP 800-53 expect an *approved baseline*, not tribal knowledge. The Governance UI columns (`standards`, `categories`, `controls`) are how an ISSO traces a green cluster back to AC-6, CM-6, SC-7, and SC-5.

== What does it solve

* EoP — workloads landing in namespaces without restricted PSA
* DoS — unbounded CPU/memory in a shared tenant namespace
* Spoofing — app ServiceAccounts that still automount API tokens
* Disclosure / lateral movement — namespaces with no default-deny NetworkPolicy
* Drift — each cluster’s “baseline” living in a different wiki

== Your Mission
Apply PolicySet `stride-ocp-baseline`, watch it NonCompliant while `inform` is on, enforce it so the cluster configures itself, then prove restricted PSA still denies a privileged pod.

[cols="1,2,2",options="header"]
|===
|Policy in the set |STRIDE row |Objects

|`policy-stride-ns-psa`
|Elevation of privilege
|Namespace `stride-workloads` + restricted PSA labels

|`policy-stride-quota-limits`
|Denial of service
|LimitRange + ResourceQuota

|`policy-stride-netpol-sa`
|Spoofing + Information disclosure
|default-deny NetworkPolicy + SA `app` with `automountServiceAccountToken: false`
|===

=== Part B: Inform (report drift)

.Apply ~/ocp5-rhacs-showroom/setup/acm-lab/policy-stride-ocp-baseline.yaml. Expect Policies, PolicySet stride-ocp-baseline, a Placement, and a PlacementBinding in namespace policies

oc apply -f ~/ocp5-rhacs-showroom/setup/acm-lab/policy-stride-ocp-baseline.yaml

[%collapsible]

[source,bash,subs="+macros,+attributes",role=execute]

=== Part C: Enforce (configure the cluster from policy)

.Patch policies policy-stride-ns-psa, policy-stride-quota-limits, and policy-stride-netpol-sa in namespace policies so spec.remediationAction is enforce. Expect three patched
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
for p in policy-stride-ns-psa policy-stride-quota-limits policy-stride-netpol-sa; do
  oc patch policy "$p" -n policies --type merge -p '{"spec":{"remediationAction":"enforce"}}'
done
----
====

.Get policies in namespace policies with label app.kubernetes.io/component=301-01-acm, show labels on namespace stride-workloads, list networkpolicy, limitrange, resourcequota, and sa there, then print automountServiceAccountToken for service account app. Expect Compliant, pod-security.kubernetes.io/enforce=restricted, default-deny-ingress, bounded-defaults, bounded-quota, and automount false
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get policy -n policies -l app.kubernetes.io/component=301-01-acm
oc get ns stride-workloads --show-labels
oc get networkpolicy,limitrange,resourcequota,sa -n stride-workloads
oc get sa app -n stride-workloads -o jsonpath='{.automountServiceAccountToken}{"\n"}'
----
====

=== Part D: Admission still matches the baseline

.Apply Pod privileged-denied in namespace stride-workloads, container app, image registry.access.redhat.com/ubi9/ubi, privileged true, command sleep 5. Expect Forbidden and violates PodSecurity
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -n stride-workloads -f - <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: privileged-denied
spec:
  containers:
  - name: app
    image: registry.access.redhat.com/ubi9/ubi
    securityContext:
      privileged: true
    command: ["sleep","5"]
EOF
----
====

== Debrief

Platform governance is the STRIDE map **as Policy**: who may change SCC and ANP is a platform decision; app teams do not freestyle namespaces. Inform then enforce is how drift is corrected. xref:301-02-gitops-policy-compliance.adoc[301-02] puts these YAML files in Git.

What breaks without this:

* Threat model with no delivery mechanism → next cluster is a snowflake
* Hand-crafted namespaces → STIG drift
* Automount left on by default → stolen tokens (Spoofing) still work

IMPORTANT: PolicySet + Placement + inform then enforce. Do not rewrite cluster `restricted` SCC in this lab.

NOTE: GitOps of these same CRs is 301-02. Tenant NetworkPolicy still cannot beat platform ANP (xref:301-03-multi-tenant-zero-trust-network.adoc[301-03]).
