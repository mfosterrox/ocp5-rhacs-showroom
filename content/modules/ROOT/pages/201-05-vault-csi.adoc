**Duration:** ~25 minutes

== Overview
Wire HashiCorp Vault and External Secrets Operator so pods get secrets at runtime without baking static copies into Git or images—dev-mode Vault for learning only.

include::partial$console-access.adoc[]

== Why it matters
Static credentials in images, manifests, and long-lived Kubernetes Secrets are prime loot after a foothold. Vault keeps the source of truth off the cluster disk and issues access on demand so a stolen YAML file is no longer enough.

== What does it solve

* Secrets committed to Git or baked into images
* Long-lived cluster Secrets with no rotation story
* Apps that cannot prove where credentials came from

== Your Mission
Stand up Vault, configure Kubernetes auth and policies, then prove a pod can consume secrets without carrying static copies—an attacker who clones the app repo still does not get the database password.

NOTE: This lab runs Vault in *dev mode* (auto-unsealed, root token `root`). Dev mode is for learning only—data is lost when the Vault pod restarts. Do not use it in production.

This lab tracks the https://github.com/validatedpatterns/layered-zero-trust[Layered Zero Trust Validated Pattern] pattern for secrets (Vault and External Secrets Operator).

.Inside vault-0, set AUD from the service account token aud claim, then write auth/kubernetes/role/vault-role with bound_service_account_names=vault-serviceaccount, bound_service_account_namespaces=vault, policies=read-policy, ttl=1h, and audience $AUD
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----

  bound_service_account_names=vault-serviceaccount \
  bound_service_account_namespaces=vault \
  policies=read-policy \
  ttl=1h \
  audience="${AUD}"

== Debrief

You consumed Vault secrets two ways—Agent Injector files under `/vault/secrets/` and External Secrets Operator sync into a native Secret—so credentials are not baked into Git or images.

What breaks without this:

* Static Secrets in etcd/Git/images → long-lived loot after a foothold
* No rotation path → stolen credentials stay valid

IMPORTANT: Vault (or equivalent) as source of truth, Kubernetes auth bound to namespace/SA, injector for file delivery, ESO when apps need native Secret mounts, and least-privilege Vault roles.

NOTE: prefer short-lived, identity-bound access over copied passwords. Lab cleanup runs `setup/vault-lab/cleanup-vault-lab.sh` via `lab-cleanup.sh --module 201-05`.
