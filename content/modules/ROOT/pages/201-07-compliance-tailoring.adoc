:toc:

**Duration:** ~25 minutes

== Overview
Re-scan **CIS** (`ocp4-cis`) after xref:201-06-audit-monitoring-correlation.adoc[201-06] so audit logging and log forwarding go green, then tailor the *same* profile for lab-only noise. Do not disable the controls you just fixed, and do not switch to `rhcos4-moderate` for this story.

== Why it matters
xref:101-10-security-compliance-addons.adoc[101-10] showed the usual CIS gap: path PASS, **forwarding FAIL**. 201-06 shipped kube-apiserver audit to Splunk with a `ClusterLogForwarder`. Auditors still want a **new** `ocp4-cis` result, not a screenshot of Splunk. Tailoring is how you document exceptions that are *not* those logging controls.

== What does it solve

* “We forwarded logs” with no CIS evidence that 1.2.21 / 3.2.1 passed
* Alert fatigue from irrelevant CIS findings (while hiding a real FAIL)
* “Waived forever” exceptions with no ownership
* Mixing RHCOS node profiles with OpenShift CIS platform audit rules

== Your Mission
Keep Splunk and the forwarder from 201-06. Re-scan `ocp4-cis`, prove audit logging and forwarding PASS, then tailor *other* FAILs. Do not disable `audit-log-forwarding-enabled` or `audit-logging-enabled`.

=== Prerequisites

* xref:201-06-audit-monitoring-correlation.adoc[201-06] completed **without** tearing down Splunk (lab cleanup for 201-06 only removes the sleeper project)
* Compliance Operator installed (`openshift-compliance`)
* Cluster-admin (or equivalent) to create scans and TailoredProfiles

CIS OpenShift 1.7 rows this pair of labs is aiming to PASS (automated, `ocp4-cis` platform profile):

[cols="1,2,2",options="header"]
|===
|CIS OCP |Rule (name contains) |What 201-06 contributed

|**1.2.20**
|`api-server-audit-log-path`
|Already on stock OpenShift; 101-09 listed the file

|**1.2.21**
|`audit-log-forwarding-enabled`
|`ClusterLogForwarder` with `inputRefs: [audit]` → Splunk HEC

|**1.2.22** / **1.2.23**
|`audit-log-maxbackup` / `audit-log-maxsize`
|Platform defaults; do not set `unsupportedConfigOverrides`

|**3.2.1** (Logging)
|`audit-logging-enabled`
|API server audit profile is not `None` (OpenShift default)

|**3.2.2** (Logging, Level 2)
|`audit-profile-set`
|Often FAIL on `Default` vs `WriteRequestBodies` — tailor or leave; do not confuse with 3.2.1
|===

OpenShift CIS 1.7 has **no** separate “Prometheus is installed” automated row. Platform monitoring (`openshift-monitoring`) is the metrics half of 201-06 correlation; you verify it is running, you do not score it as CIS 1.2.21.

NOTE: `audit_log_forwarding_uses_tls` and `audit_error_alert_exists` are STIG/NIST-oriented. Stay on `ocp4-cis` for this lab.

=== Part A: Prove 201-06 against CIS

.Check that a ClusterLogForwarder pipeline in openshift-logging lists inputRefs audit, for observability.openshift.io and for logging.openshift.io instance. Expect true
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
echo "=== observability.openshift.io ==="
oc get clusterlogforwarders.observability.openshift.io -n openshift-logging -o json 2>/dev/null \
  | jq -r '[.items[]?.spec.pipelines[]?.inputRefs[]?] | index("audit") != null' \
  || echo "n/a"
echo "=== logging.openshift.io instance ==="
oc get clusterlogforwarder.logging.openshift.io instance -n openshift-logging -o json 2>/dev/null \
  | jq -r '[.spec.pipelines[]?.inputRefs[]?] | index("audit") != null' \
  || echo "n/a"
oc get clusterlogforwarder -n openshift-logging 2>/dev/null || true
----
====

.Get the first 20 pods in namespace openshift-monitoring. Expect cluster-monitoring-operator, Prometheus, and Alertmanager Running
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get pods -n openshift-monitoring | head -20
----
====

.If a ComplianceScan in openshift-compliance ends with ocp4-cis, annotate it compliance.openshift.io/rescan=. Otherwise apply ScanSettingBinding 201-07-cis in openshift-compliance for Profile ocp4-cis and ScanSetting default, then list ComplianceScans. Expect phase DONE
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
SCAN=$(oc get compliancescans -n openshift-compliance -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}' \
  | grep -E 'ocp4-cis$' | head -1)
if [ -n "$SCAN" ]; then
  echo "Rescanning $SCAN"
  oc annotate compliancescan "$SCAN" compliance.openshift.io/rescan= --overwrite -n openshift-compliance
else
  oc apply -f - <<'EOF'
apiVersion: compliance.openshift.io/v1alpha1
kind: ScanSettingBinding
metadata:
  name: 201-07-cis
  namespace: openshift-compliance
profiles:
- name: ocp4-cis
  kind: Profile
  apiGroup: compliance.openshift.io/v1alpha1
settingsRef:
  name: default
  kind: ScanSetting
  apiGroup: compliance.openshift.io/v1alpha1
EOF
fi
oc get compliancescans -n openshift-compliance
----
====

.List compliancecheckresults in openshift-compliance matching audit-log, audit-logging, or log-forward. Expect PASS for audit-log-forwarding-enabled and audit-logging-enabled
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get compliancecheckresults -n openshift-compliance --no-headers \
  | grep -iE 'audit-log|audit-logging|log-forward' \
  || echo 'No audit-log results yet -- wait for DONE, then re-run.'
----
====

.List compliancecheckresults in openshift-compliance matching audit-log, audit-logging, log-forward, or audit-profile where STATUS is anything except PASS. Expect empty, or only audit-profile-set FAIL
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get compliancecheckresults -n openshift-compliance --no-headers \
  | awk 'tolower($0) ~ /audit-log|audit-logging|log-forward|audit-profile/ && toupper($2) != "PASS" {print $1, $2, $3}'
----
====

=== Part B: Tailor CIS noise — not the logging controls

.List up to 15 FAIL compliancecheckresults in openshift-compliance excluding names that match audit-log, audit-logging, or log-forward, and show annotation compliance.openshift.io/rule
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc get compliancecheckresults -n openshift-compliance -o json \
  | jq -r '
    .items[]
    | select((.status|tostring|ascii_upcase|contains("FAIL")))
    | select(.metadata.name | test("audit-log|audit-logging|log-forward";"i") | not)
    | "\(.metadata.name)\t\(.metadata.annotations["compliance.openshift.io/rule"] // "no-rule-annotation")"
  ' | head -15
----
====

.Apply TailoredProfile ocp4-cis-lab in openshift-compliance extending ocp4-cis, disabling rule ocp4-kubeadmin-removed because lab clusters keep kubeadmin for attendee login
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: compliance.openshift.io/v1alpha1
kind: TailoredProfile
metadata:
  name: ocp4-cis-lab
  namespace: openshift-compliance
spec:
  title: ocp4-cis-lab
  description: Roadshow CIS — keep audit logging and forwarding; disable lab-only kubeadmin.
  extends: ocp4-cis
  disableRules:
    - name: ocp4-kubeadmin-removed
      rationale: Lab clusters keep kubeadmin for attendee login. Production must remove kubeadmin after an identity provider is configured.
EOF
----
====

.Apply ScanSettingBinding 201-07-cis-lab in openshift-compliance for TailoredProfile ocp4-cis-lab and ScanSetting default, then list ComplianceScans. Expect the new scan phase DONE
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: compliance.openshift.io/v1alpha1
kind: ScanSettingBinding
metadata:
  name: 201-07-cis-lab
  namespace: openshift-compliance
profiles:
- name: ocp4-cis-lab
  kind: TailoredProfile
  apiGroup: compliance.openshift.io/v1alpha1
settingsRef:
  name: default
  kind: ScanSetting
  apiGroup: compliance.openshift.io/v1alpha1
EOF
oc get compliancescans -n openshift-compliance
----
====

.Compare stock ocp4-cis and tailored cis-lab compliancecheckresults in openshift-compliance for audit-log, audit-logging, and log-forward. Expect forwarding and audit-logging-enabled still scored
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
echo "=== stock ocp4-cis (audit/logging) ==="
oc get compliancecheckresults -n openshift-compliance --no-headers \
  | grep -iE 'ocp4-cis-.*audit-log|ocp4-cis-.*audit-logging|ocp4-cis-.*log-forward' \
  | grep -v cis-lab || true
echo "=== tailored ocp4-cis-lab (audit/logging) ==="
oc get compliancecheckresults -n openshift-compliance --no-headers \
  | grep -iE 'cis-lab.*audit-log|cis-lab.*audit-logging|cis-lab.*log-forward' \
  || true
----
====

NOTE: Auto-apply of ComplianceRemediations is for non-prod iterative hardening only. Do **not** apply remediations that patch kube-apiserver `unsupportedConfigOverrides` to silence maxsize/maxbackup. Prefer a change ticket and a rescan.

== Debrief

201-06 implemented CIS **1.2.21** (forward audit off-cluster) and left **3.2.1** (audit enabled) intact. 201-07 is the Compliance Operator receipt: rescan `ocp4-cis`, then tailor only documented lab exceptions.

What breaks without this:

* Untailored profiles → alert fatigue and ignored findings
* Tailoring away forwarding → a green report that lies about 201-06
* Scanning `rhcos4-moderate` here → you never re-score OpenShift CIS logging

IMPORTANT: tailored profiles, scan comparison, never disable `audit-log-forwarding-enabled` / `audit-logging-enabled` to pass the demo.

NOTE: document why a check is disabled; re-scan after 201-06 and after tailoring. Splunk teardown runs with this module’s cleanup.
